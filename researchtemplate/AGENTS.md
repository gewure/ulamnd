# Standing instructions for any agent working in this repository

This is a research programme, not a codebase. Read this file, then `research/KNOWLEDGE.md` §0b, before
doing anything else. If `research/KNOWLEDGE.md` still contains `{{...}}` placeholders, the programme has
not been initialized: run `prompts/00-initialize.md`.

## Order of reading at the start of a session

1. `research/KNOWLEDGE.md` §0b — where things stand, what to do next, what not to claim.
2. `research/KNOWLEDGE.md` §3 and `research/RULES-INHERITED.md` — the errors already made, and the rules.
3. `research/ERRATA.md` — the tail, for anything recorded but not yet applied.
4. The `STATUS.md` of whatever document you are about to touch; `research/explore/STATE.md` if an
   exploration is in progress.

Do not re-derive what is recorded. Do not trust your own summary of past sessions over these files.

## The rules that are not negotiable

1. **No number without a script.** Every figure, constant, table entry and exponent in any document comes
   from a script in this repository, named next to it, with its output in the document's `data/`. You may
   not type a number you computed in your head or remember from training. If a number cannot be
   regenerated by a command, it does not go in.
2. **Every constant by two independent routes.** Different derivations, not the same script twice.
3. **Label every statement.** Proved / proved under a stated hypothesis / conjectured with numerical
   support / refuted / untested. A statement with no label is a bug. The status board in
   `KNOWLEDGE.md` §2 holds the labels, and the document must agree with it.
4. **Correct or leave open.** If a claim breaks, either repair it or mark it open and say exactly what is
   missing. Never replace it with a weaker claim about a different object, and never quietly narrow the
   object while keeping the headline.
5. **Same-day errata.** An error found in an abstract, theorem, conjecture or headline claim is written to
   `ERRATA.md` *and* applied to the document the same day, or the document is marked *do not circulate* at
   the top.
6. **Write down every error you make**, in `KNOWLEDGE.md` §3, in the form: what was claimed, why it is
   wrong, how it was found, and the general rule that would have prevented it. Errors are the most
   valuable output of a session. Never delete one; never soften one.
7. **Cite only what you have read.** Before invoking a result, state its hypotheses and check each one
   against the object at hand. If you have not read the source, say so and mark the citation unverified in
   `research/LITERATURE.md`.
8. **Never claim novelty** without a named literature check recorded in `research/LITERATURE.md`.
9. **A mechanism needs a testable consequence.** Before writing up an explanation, derive something it
   predicts that a computation can check, and check it. A story that predicts nothing is not written up.
10. **Respect the do-not-claim list** in `KNOWLEDGE.md` §0b. Ask the author before removing an item; add
    items freely.
11. **Record external actions only when the author confirms them.** Submissions, uploads, messages sent,
    anything outside the repository. An intention is not an event.
12. **The generator is not the checker.** When a proof, a derivation or a document is finished, it goes to
    a reader with no session context (`prompts/02-adversarial-reading.md`). Your own second pass does not
    count as a reading.

## How to work

- **Test-driven.** A claim becomes a registered test in `research/experiments/claims.py` before it is
  believed. Run the suite; record what came out, including refutations of things the author believes.
  Refuting the author's claim is a success, and is reported plainly, without hedging.
- **Two routes for anything that matters**, one of them numerical wherever a numerical route exists.
- **Enumerate and rate.** When there are several ways forward, list them all in
  `research/RESEARCH-USES.md` with a rating and, for each, what would have to be true for it to work and
  what cheap test would tell us first. Then recommend one. Do not silently pursue the first idea.
- **Explain at the level where the author can decide.** Their level is stated in `PROJECT-BRIEF.md` §5.
  Give the decision, the alternatives, and the consequence of being wrong — not a lecture, and not a
  summary so smooth that agreeing is the only possible response.
- **Effort estimates** come with a range and a confidence, and are recorded when they turn out wrong.
- **Keep the state current.** Long explorations write `research/explore/STATE.md` as they go, for pick-up
  by someone with no context: what was tried, what the numbers were, what to do next, in order.
- **Scratch work** goes in `research/explore/`, with its logs and data. It is allowed to be messy; it is
  not allowed to be undated or unexplained.

## Documents

Each document lives in its own directory with `main.tex` (or equivalent), `refs.bib`, `STATUS.md`,
`scripts/`, `data/`. `STATUS.md` says, in dated entries: what is proved, what is open, what each number's
script is, and every reading the document has had. A document nobody outside the session has read says so
at the top.

## Housekeeping

- Commit messages: what changed and why, including the erratum number if one is being applied.
- Never rewrite history in `ERRATA.md`, `KNOWLEDGE.md` §1 (timeline) or `research/reviews/`.
- Archive every outside assessment with the revision hash it assessed: `reviews/YYYY-MM-DD-<what>-<hash>.*`.
- `python3 scripts/audit.py` runs the mechanical hygiene checks. It is not a substitute for reading.
